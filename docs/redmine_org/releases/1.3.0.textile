h3. redmine_expert_metrics 1.3.0 — 2026-10-12

h4. Added

* *API usage page* (_Administration → expert Metrics → API usage_, also as JSON), *opt-in* via the plugin setting _Record API usage_ (off by default; while off, API requests cost nothing extra and @/metrics@ runs no API queries). Redmine keeps no record of when an API key is used; with the setting on, the plugin records every request authenticated by API credentials and shows, per user, the number of requests, the writing ones (POST, PUT, PATCH, DELETE), the authentication method (API key, API key as HTTP Basic user, login and password via HTTP Basic — highlighted, OAuth), the clients by User-Agent, the last IP address and path, and when the key was created. A second table lists API keys that were not used in the selected period (today, 7, 30 or 90 days). Requests sent with @X-Redmine-Switch-User@ are booked on the key owner.
* *Prometheus* (while recording is on): @redmine_api_requests_total{method,auth}@, @redmine_api_users{window}@ and @redmine_api_keys_total@ — aggregates only, no names.
* *Grafana dashboard*: new *REST API* row with API users, key holders and requests per hour by method and by authentication.

h4. Upgrade notes

Migration 002 adds the table @expert_metrics_api_usages@ — run the migration command and restart. Nothing is recorded until you switch on _Record API usage_ under _Administration → Plugins → Configure_; there is no history from before the upgrade.

The table stores the last IP address and the User-Agent per user and client, as daily aggregates, and is purged after 90 days. Mention it in your privacy documentation.
